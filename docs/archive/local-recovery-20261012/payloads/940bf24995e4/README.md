# 脚本目录使用说明

## 当前入口边界

- `scripts/*.py`：仍在维护的核心算法模块和直接运行入口。这里的旧文件依赖同级 `import`，在完成包化重构前不可仅为美观而移动。
- `scripts/maintenance/`：目录审计、迁移、发布核验、一次性检查工具。新建维护脚本必须放入此处。
- `scripts/validation/`：ECG、呼吸带（RSP）和外部金标准验证入口。目录已预留，新的验证入口不得再放根层。
- `scripts/analysis/`：珠海、北京正式实验、预实验和多模态分析入口。目录已预留，新的分析入口不得再放根层。
- `scripts/shared/`：无业务入口的可复用模块。新模块须提供最小单元测试或调用示例。
- `scripts/legacy/`：历史脚本、临时诊断和已替代版本，只读保留，不作为正式分析入口。

## 运行规则

1. 不允许通过 `latest`、`FAST`、`FULL`、`test2` 等名字创建新脚本或输出目录。
2. 新脚本优先通过 `path_registry.py` 和 `configs/paths.local.json` 解析本机数据根目录，不把移动硬盘盘符写死到代码中。
3. 写入结果前，必须指定规范 `output/` 分类目录，并在结果中记录输入、参数、生成脚本和证据状态。
4. 移动现有核心模块前，先完成导入图审计和 `python -m py_compile` 验证；禁止只为整理文件名而破坏历史复现。

完整规范见 [`docs/00_治理/算法库目录与命名规范_v1.md`](../docs/00_治理/算法库目录与命名规范_v1.md)。
