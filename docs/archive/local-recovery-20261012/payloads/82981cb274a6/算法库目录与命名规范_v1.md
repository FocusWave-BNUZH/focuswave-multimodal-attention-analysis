## 2. 输出目录规则

每项结果的主目录由“证据用途”决定，不再以临时日期、被试编号或算法昵称直接放在 `output/` 根目录。

| 目录 | 放入内容 | 示例 |
| --- | --- | --- |
| `00_索引与审计` | 数据源可用性、输入清单、迁移映射、版本审计 | `J_Data_被试场次审计_v1` |
| `10_质量控制` | 时间轴裁剪、质量门控、缺失与失败审计 | `J_Data_行为时间门控_v1` |
| `20_生理金标准验证` | ECG/RSP 清洗、毫米波参照验证、外部基准 | `ACQ_ECG_RSP参考清洗_v1` |
| `30_预实验与原型` | 预实验、近场、深呼吸、原型性试验 | `预实验_生命体征质量_v5` |
| `40_正式实验` | 仅正式任务与正式毫米波分析 | `J_Data_毫米波窗口分析_v1` |
| `50_多模态与报告` | NIR/RGB、多模态模型、报告表图 | `J_Data_多模态LOSO_v1` |
| `90_历史归档` | 被新版本替代但必须保留追溯的输出 | `2026-08_旧批次全程分析` |
| `99_运行临时` | 未登记的中间物、下载或短期检查 | 必须在任务结束前转正或归档 |

目录内名称使用：`数据范围_分析主题_版本`。例如 `J_Data_警觉度事件锁定_v1`、`ACQ_金标准参照再审计_v1`。不得使用 `FAST`、`FULL`、`最新`、`新建文件`、`最终版` 等无法说明分析范围与证据等级的名称。

## 3. 新文件的最小元数据

正式 Markdown 报告、JSON 汇总和结果目录必须包含或链接到以下信息：

1. 输入数据根路径与数据版本；
2. 生成脚本、脚本提交版本或内容哈希；
3. 参数和质量门控；
4. 输出范围、行数/文件数与生成时间；
5. 证据状态：`confirmatory`、`exploratory`、`sensitivity`、`historical` 或 `audit`；
6. 替代或被替代关系。

## 4. 迁移与删除边界

- 先生成迁移清单并以“复制校验后移动”的方式实施；不覆盖同名目标，不删除源文件。
- 每批移动后检查文件数、总字节数、SHA-256（对小型文本）和脚本旧路径引用。
- 任何包含 `.npz`、`.bin`、`.acq`、视频、模型缓存或虚拟环境的目录不进入 Git，也不在运行中移动。
- 旧路径仅在所有依赖脚本和项目索引更新、最小运行验证通过后删除空目录。
- `output/` 本身仍被 Git 忽略；本规范、迁移脚本与小型索引可提交。

## 5. 本轮验收标准

1. 根目录不再新增无归属的脚本、结果或临时文件；
2. `output/` 根目录只保留上述八个分类目录和 `README.md`；
3. 每个现有顶层输出都有迁移映射、来源脚本和风险状态；
4. 所有移动均能在清单中回溯，且不改变原始数据；
5. 代码中不存在未登记的旧输出路径引用；
6. Git 不纳入 `output/`、数据、虚拟环境、缓存或原始二进制。
