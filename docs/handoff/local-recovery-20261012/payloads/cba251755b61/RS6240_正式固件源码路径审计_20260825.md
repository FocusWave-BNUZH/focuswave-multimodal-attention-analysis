### 1. 参数与模式

`ReportDataCube1D/src/prj_config.h` 当前可见：

```text
RADAR_FRAMEWORK_SAMPLE_START_FREQ_MHZ = 57000
RADAR_FRAMEWORK_SAMPLE_MIMO_MODE = MMW_MIMO_2T4R
RADAR_FRAMEWORK_SAMPLE_RFFT_LEN_LOG2 = 8
RADAR_FRAMEWORK_SAMPLE_RANGE_RESOLUTION_MM = 37
RADAR_FRAMEWORK_SAMPLE_DFFT_LEN_LOG2 = 5
RADAR_FRAMEWORK_SAMPLE_VEL_RESOLUTION_MM = 250
RADAR_FRAMEWORK_SAMPLE_FRAME_PERIOD_MS = 10
```

但同一文件的当前配置是：

```text
CONFIG_RADAR_FRAMEWORK_FFT_MODE = RADAR_FRAMEWORK_ADC_MODE
```

并在注释中写明是 2026-08-12 的实验性 `2DFFT → ADC` 修改。文件修改时间为 2026-08-12，而正式镜像构建日期为 2026-07-24，所以当前文件不能作为 formal exact source。

### 2. DataCube 报告与通道顺序

参考框架的 `radar_signal_process_1d.c` 在 1D 回调中调用：

```text
radar_framework_ctrl_data_cube_report_cb(mmw_data, arg)
```

在非 report 示例分支中，源码按 `tx_idx` 外层、`rx_idx` 内层调用 `__mmw_fft_range()`，并连续递增 DataCube 指针。这支持参考实现中的逻辑顺序：

```text
0 tx0_rx0, 1 tx0_rx1, 2 tx0_rx2, 3 tx0_rx3,
4 tx1_rx0, 5 tx1_rx1, 6 tx1_rx2, 7 tx1_rx3
```

实际数据核验也发现三个 ECG/RSP 校准场次的 NPZ key 均是这 8 个 key，每路 shape 为 `(1000, 256)`，dtype 为 `complex128`。这确认了主机侧 key 结构，但还不足以证明正式镜像内部物理内存布局在所有环节中完全相同。

### 3. Calibration 路径

参考树中 `mmw_ctrl.c` 在 `CONFIG_MMW_CALIB_DATA_LOAD` 条件下调用 `mmw_ant_calib_data_load()`。`mmw_alg_ant_calibration.c` 对 RS624x 读取 `HWINFO_ID_NVM_ANT_CALIB_2T4R`，并提供 8 路复数系数及 `mmw_cube_ant_align_2t4r()` 复数乘法。

但是，当前 `radar_signal_process_1d.c` 的 report 分支只调用 `radar_framework_ctrl_data_cube_report_cb()`，没有在该文件中直接出现 `mmw_cube_ant_align_2t4r()`。由于 MMW 控制库/固件链接状态、exact build 宏值、板卡 NVM 内容以及 ReportDataCube1D 的库内调用点均未被 exact build 证据覆盖，当前只能写：

> SDK 参考实现包含加载 2T4R 天线校准系数的路径；正式 `ReportDataCube1D` 输出是否实际使用该校准、使用哪组 NVM 系数，仍未确认。

不能写成“正式 NPZ 已经经过官方天线校准”。

## Codex 首次执行后的十问回答

1. **exact 2026-07-24 source tree？** 未找到。找到 SDK V2.1.0 参考树，但无能对应镜像 SHA 的 Git/hash/构建日志。
2. **正式 `prj_config.h` 完整参数？** exact source 未找到。参考配置确认 57 GHz、2T4R、RFFT 256、37 mm、DFFT 32、250 mm/s、10 ms，但当前 FFT mode 被后续实验改成 ADC，不能当 formal exact source。
3. **Tx0/Tx1 发射顺序？** 未确认。当前参考树只确认 MIMO 模式和逻辑 tx/rx 遍历，不能证明正式固件真实 TDM/chirp 顺序。
4. **Tx 间/chirp 间真实 interval？** 未确认。参考 1D 框架默认 `100 us`；FocusWave 的 `57 us` 是代码默认并明确标作 SDK demo 默认。
5. **8 路内存顺序是否完全对应？** 主机 NPZ key 和参考循环均支持 `tx0_rx0 ... tx1_rx3` 的逻辑顺序；正式镜像内部内存布局仍未完成 exact proof。
6. **ReportDataCube1D 是否实际执行 antenna calibration？** 未确认。SDK 存在加载 2T4R NVM 系数的路径，但 exact build 宏、NVM 系数和 1D report 链接内实际应用点缺证。
7. **同 Tx/跨 Tx cardiac-band coherence？** 首轮 3 场次 60 秒窗口的均值约为 0.458 vs 0.476，未见同 Tx 明显优势。
8. **是否支持 same-Tx 4Rx phase fusion？** 只支持作为下一步实验性候选，不支持冻结为已验证方案；需要固定 range/窗口策略并通过 ECG。
9. **C8-PH 相对 S1 的 ECG IBI？** 尚未运行，因此没有改善结论。
10. **是否进入 complex coherent fusion？** 不进入。阻塞项是 exact calibration 状态、Tx/chirp timing、跨 Tx 相位稳定性和 ECG 逐搏优越性均未同时满足。
